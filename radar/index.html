worktrunk↗

Rust 写的 Git worktree 管理 CLI，专为「同时跑多个 AI 编码 agent」设计：一条命令给每个 agent 开一棵独立 worktree + 分支，各自在自己的工作树里改代码互不踩踏，跑完再合并回主干。6k+ star，官网 worktrunk.dev。

为什么收藏 · 多 agent 并行开发时的 worktree 编排层——重度用 Claude Code 最先撞到的就是这道墙。
项目 github.com/h0ngcha0 收藏于 2026-07-27

hubo↗

把周伯通的「双手互搏」搬进 coding agent：不是一个 agent 自己审自己，而是实现方与审查方两个持久角色在同一会话里对抗——一方交实现与证据，另一方挑错，来回到每条 review 意见都被 reconcile 收敛，才交到人手上；另有「主审 ↔ 抬杠审」模式专门打掉误报、补回漏检。MIT，2026 年 7 月底刚发布的早期项目（约 26 star），胜在理念而非成熟度。

为什么收藏 · 对抗式 self-play review 的思路，可借鉴进自建 agent 车队的 code-review 环节。
阅读 handbook.modular.com 收藏于 2026-07-23

LLM Inference Handbook↗

Modular（Mojo 语言 / MAX 推理平台背后的公司）出的开放在线手册，自我定位「技术词典 + 指南 + 参考书」三合一，专治 LLM 推理知识的碎片化——它散在论文、厂商博客、GitHub issue 和 Discord 里，而且大多默认你已经懂半个栈。七大板块：推理基础与指标（TTFT / ITL / TPOT，以及为什么 goodput 比裸吞吐更重要）→ 部署规划（选模型、选 GPU、选推理框架，显存怎么算，Serverless 还是自托管，BYOC 与本地部署）→ 模型准备（量化 / 微调 / 蒸馏）→ 模型交互（OpenAI 与 Anthropic 兼容 API、function calling、结构化输出、MCP）→ 推理优化（continuous batching、chunked prefill、PagedAttention、prefix caching、KV cache offloading、投机解码、prefill-decode 分离、并行策略与推理路由）→ kernel 优化（GPU 架构基础、FlashAttention）→ 基础设施与运维（分布式推理、快速扩缩容、可观测性、多云跨区、成本）。配 20+ 个可上手玩的交互件：批处理策略模拟器、延迟时间线、上下文窗口模拟器、GPU 显存与 KV cache 计算器、Top-p vs Top-k 对比等。Apache-2.0 开源。

怎么用 · 当体系化查阅书使：先顺着目录读一遍建立全局，之后遇到具体问题（选卡、算显存、要不要上投机解码）再回来查对应章节。对 agent 也友好——任意页面网址后加 .md 就能取 Markdown 原文，站点还提供 llms.txt 全站索引。

LiteLLM↗

开源 AI 网关的事实标准：一个 OpenAI 兼容端点接进 100+ 家模型（OpenAI / Anthropic / Gemini / Bedrock / Azure / VertexAI / vLLM / NIM…），内置成本追踪、负载均衡、自动 fallback 与重试、预算与限速、缓存和 guardrails，可当 proxy 自托管。Rust 核心 + Python SDK，5 万+ star，几乎每天都在更新。

为什么收藏 · 摆在自建 agent 车队前面做统一模型接入层，和同在这页的 agent-vault 凭证代理天然配套。
工具 github.com/diegosouzapw 收藏于 2026-07-21

OmniRoute↗

同样是自托管 AI 网关，但更偏「智能选模型」：本地 proxy + OpenAI 兼容端点，BYOK 聚合数百家 provider（含一批带免费额度的），原生对接 Claude Code / Codex / Cursor / Cline / Copilot；差异化在十几种路由策略（成本优先、剩余额度优先、多模型 + 裁判、实时打分自动选）和内置的 prompt 压缩（与同页收录的 headroom 同路）。MIT，TypeScript，5 万+ star。README 里部分指标偏营销口径、免费额度聚合也较脆弱，按需取用。

为什么收藏 · 和 LiteLLM 并存的另一半：LiteLLM 是生产级接入基础设施，它是 coding-agent 优先、自带压缩的日用款。

工具 github.com/headroomlabs-ai 收藏于 2026-06-19

headroom↗

AI Agent 的「上下文压缩层」：prompt、工具输出、日志、RAG、对话历史送进 LLM 之前先压一道：coding agent 场景省约 20%，JSON / 日志这类结构化输出省 60–95%，答案不变。三种接入方式——库调用、本地 proxy 零改码、MCP server，另有 headroom wrap claude·codex·cursor 一键包裹。实现是 Python 编排 + Rust 引擎：统计分析器判定 JSON 数组可压性后做抽取式 k-split、AST 级代码压缩、可逆压缩（原文落本地、prompt 里只留 hash 标记，模型要时再取回）、以及护住 provider KV-cache 前缀的告警器。Apache-2.0，6 万+ star。
项目 github.com/OpenBMB 收藏于 2026-06-15

VoxCPM2↗

OpenBMB（MiniCPM 团队）开源的 2B 参数 Tokenizer-Free TTS，扩散自回归架构：支持 30 语种 + 自动语种识别、用自然语言描述做「声音设计」、可控音色克隆（情感 / 语速 / 表达）、48kHz 录音棚级音质，4090 上 RTF≈0.3 实时流式。Apache-2.0，代码与权重全开源，3 万+ star。
框架 github.com/omnigent-ai 收藏于 2026-06-14

Omnigent↗

Databricks 的 Matei Zaharia 团队开源的多 agent meta-harness（Apache-2.0）：统一界面架在 Claude Code、Codex、Pi 及自定义 agent 之上，用「策略」而不是 prompt 做管控，live session 跨终端 / Web / 手机同步并支持实时协作，本地优先、无云依赖。

为什么收藏 · 做「不止 Claude Code」的多 agent 系统时，可复用的编排、管控与跨端协作底座。
