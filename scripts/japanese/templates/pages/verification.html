真实拦下的错误

这些不是假设——下面每一条都是校验过程中实际出现、并因此没有上线（或被修正）的问题：

  • 单个汉字被读成音读：「雲」读成うん、「月」读成がつ、「骨」读成こつ、「心」读成しん……（Whisper large-v3-turbo 与 large-v3 两个模型的转写一致）合成引擎单念一个汉字时常用音读。这些词改用假名输入重新合成，再次通过读音校验后才采用（同音词组除外：假名输入会丢掉「是哪个词」的信息，所以同音词组从不使用这种替代）。
  • 单假名被当成助词：单独的「へ」两种声音都被转写为「え」，音素识别也没有听到 h——像是读成了助词读音；改用片假名「ヘ」输入后重新校验。
  • 同音词被合成成同一段音频：女声的「雨」（头高①）和「飴」（平板⓪）输出了逐字节相同的文件——至少有一个声调是错的。音高实测拦下了不符合的那个。
  • 读错字：单独念「端」（はし）被读成了「たん」。
  • 声调不符（人工核验发现）：女声的「秋」（头高①）听起来是先低后高，已从第 7 课剔除，只用男声。
  • 静音：女声的「こ。」，以及男声的「ん」和不带句号的「あ」，合成出来都是静音。「こ」改用其他写法重新合成后通过；男声的「ん」始终不行，那一格只提供女声。
  • 句末降调掩盖声调：最初用「〜が」做检测句时，句末自然下降让「橋が」和「端が」几乎一样（差不到 1 个半音），检测句因此改成「〜があります」。

上线规则：四条全部满足

  1. 引擎检查：引擎对输入的分析必须正好是一拍，辅音和元音与预期一致（{% for c in VV_REP.clips.values() if c.voice == VV_VOICES[0] %}{% set e = c.variants[0].checks.engine.expected %}{{ c.kana }} = {{ e.consonant or "" }}+{{ e.vowel }}{{ "，" if not loop.last }}{% endfor %}），中间没有停顿。
  2. 信号检查：与其他音频相同（原始峰值高于 −35 dB，有效发声 ≥ 60 毫秒）。
  3. 音素识别：wav2vec2 国际音标识别必须听出正确的辅音类别和元音。
  4. 反向听写：Whisper large-v3-turbo，或带领域提示「{{ VV_REP.prompt }}」的 Whisper large-v3，转写出这个假名。判定比其他假名更严：转写比假名多出来的部分，只能是促音「っ」或同一个元音的拉长（「ー」、元音本身，或 e 段后的「イ」、o 段后的「ウ」）——「シェイ」「シェー」「シェッ」算シェ，「シェア」不算。（其他假名的判定允许去掉末尾任意一个元音。）

Microsoft 声音的单假名只要音素识别和转写之一通过即可上线；这几个音恰恰是识别模型最容易听错的，所以这里要求两类独立的模型（音素识别、Whisper）同时认可，再加上引擎本身的检查。

每个音、每个声音合成五次：语速 {{ VV_REP.speed_scale }} 倍（对应 Microsoft 单假名所用的 −10% 设置；两个引擎的默认语速本身不同）下用三种写法输入——假名记法（直接指定这一拍）、片假名文本、平假名文本。三种写法经过引擎里不同的处理路径，得出的音拍和音频却完全相同（这本身说明引擎对这几个音的理解没有歧义），所以只算一条。另外用假名记法再合成语速 1.0（自然语速）和 0.8（更慢，每个音段更长、更容易听清）各一条。按 {{ VV_REP.speed_scale }} → 1.0 → 0.8 的顺序，第一条四项检查全部通过的上线；全部记录如下表。
